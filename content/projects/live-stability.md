> **목적** — CrashSight 콜스택으로 재현 어려운 크래시·아웃게임 이슈를 원인까지 종결해 라이브 안정성 확보
>
> **성과** — 동일 유형 크래시 구조적 차단, 저사양·특정 그래픽 라이브러리 기기 대응
>
> **기여** — freed-tick 근본 차단, CrashSight 콜스택 추적, 퍼블리셔/아웃게임 이슈 대응


## 비동기 / 레이스 컨디션 — 원인까지 추적한 사례

- 재현 어려운 비동기·플랫폼 한정 크래시 → 증상 대응 아닌 원인까지 **구조적 차단** 원칙
- **CrashSight 콜스택 추적** — 라이브 크래시 리포트의 콜스택을 코드베이스와 대조해 원인 함수·수명 경계를 좁혀 추적

### ① 액터 풀링 × 비동기 로드 — freed-tick 크래시
- **증상** — 풀 재사용 × 비동기 로드 완료 중첩 시 freed 메모리 접근 크래시 (저재현)
- **원인** — 액터만 숨기고 컴포넌트 Tick 미정지 → Niagara `bAutoDestroy` 자기 파괴 후 freed 메모리 Tick 접근
- **원인** — 반납 시 `FStreamableHandle` 미취소 → 뒤늦은 로드 완료 콜백의 죽은 컨텍스트 참조
- **해결** — 풀 입출고 시 모든 컴포넌트 Tick 토글 + 반납 시 `FStreamableHandle` 취소 → 수명 경계 정리 명시화, 동일 유형 구조적 차단 ([최적화 페이지](/projects/optimization/) 참고)

### ② 저사양 · 특정 그래픽 라이브러리 모바일 기기 한정 크래시
- **증상** — 특정 저사양 기기 또는 특정 그래픽 라이브러리 사용 기기에서만 재현되는 크래시 (개발 환경 미재현)
- **추적** — CrashSight 리포트의 디바이스·GPU·드라이버 정보로 발생 기기군을 좁혀 특성별 분기 원인 특정
- **대응** — 기기 특성에 맞춘 렌더링/기능 분기·폴백으로 저사양 대역 안정화

- 미니맵 좌표 NaN 방어·순례 보상 정산·장비 중복 착용/미장착 슬롯·플랫폼 한정 크래시 등 다수 핫픽스

## 아웃게임 / 퍼블리셔 이슈 대응

- 게임 로직 밖 **퍼블리셔·운영 계층 이슈**도 클라이언트 관점에서 원인 확인·대응
- **해외 로그인 차단** — 특정 지역 로그인 실패 현상을 인증 플로우·플랫폼 SDK 응답 대조로 원인 확인·대응
- **운영툴 계정 잠금** — 운영툴 계정 잠금 상태의 클라이언트 처리·안내 흐름 대응
