> **목적** — 재현 어려운 비동기·레이스 크래시를 원인까지 종결해 라이브 안정성 확보
> **성과** — 동일 유형 크래시 구조적 차단, 회귀 추적으로 재발 방지
> **기여** — freed-tick·서버-클라 레이스 근본 차단, Jira 연계 회귀 추적·핫픽스

## 비동기 / 레이스 컨디션 — 원인까지 추적한 사례

- 재현 어려운 비동기·플랫폼 한정 크래시 → 증상 대응 아닌 원인까지 **구조적 차단** 원칙

### ① 액터 풀링 × 비동기 로드 — freed-tick 크래시
- **증상** — 풀 재사용 × 비동기 로드 완료 중첩 시 freed 메모리 접근 크래시 (저재현)
- **원인** — 액터만 숨기고 컴포넌트 Tick 미정지 → Niagara `bAutoDestroy` 자기 파괴 후 freed 메모리 Tick 접근
- **원인** — 반납 시 `FStreamableHandle` 미취소 → 뒤늦은 로드 완료 콜백의 죽은 컨텍스트 참조
- **해결** — 풀 입출고 시 모든 컴포넌트 Tick 토글 + 반납 시 `FStreamableHandle` 취소 → 수명 경계 정리 명시화, 동일 유형 구조적 차단 ([최적화 페이지](/projects/optimization/) 참고)

### ② 별자리 룰렛 — 서버-클라 결과 불일치 (레이스 컨디션)
- **증상** — 룰렛 결과 서버·클라 간헐적 불일치 (저재현)
- **추적** — 서버 Notify 도착 시점 × 연출 상태 전이 시점 로그 대조 → Notify 도착 순서별 결과 분기 **순서 의존성** 특정
- **원인** — 클라 결과 확정 기준이 연출 상태 → 네트워크 지연에 따른 Notify 도착 순서 레이스 구조
- **해결** — 결과 확정을 **서버 Notify 단일 기준**으로 일원화 + 연출 전이 순서 고정 → 순서 의존성 제거

- 미니맵 좌표 NaN 방어·순례 보상 정산·장비 중복 착용/미장착 슬롯·플랫폼 한정 크래시 등 다수 핫픽스
